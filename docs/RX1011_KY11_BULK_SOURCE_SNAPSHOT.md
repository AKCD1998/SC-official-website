# Rx1011 KY11 historical bulk source snapshot

The authenticated Rx1011 backend stores the exact combined sales/lot CSV for 2026-06-18 through 2026-09-27 in `ky11_bulk_source_snapshots`. Only an `ADMIN` bearer token can read `GET /api/rx1011/reports/ky11-bulk-source-snapshots/stockday-20260618-20260927-dev-v1`. The response is the original CSV, including its BOM, and is checked against SHA-256 before serving. The frontend loads it automatically when its catalog is available; manual CSV upload remains available.

The source contains 3,209 sale rows and 97 lot rows across 27 products and four branches. Nineteen lot rows use staff paper-confirmed branch lots and quantities; their `2026-02-01` date is the paper document header date, not a recorded item-level receipt date. The other 78 lot rows retain simulated development dates/capacities. The source status is `DEVELOPMENT_REFERENCE`, so this snapshot preserves a reproducible input; it does not establish verified stock receipts or make the resulting documents ready for official submission.

The data file is not committed to either public repository. Migration `0028_ky11_bulk_source_snapshots.sql` creates the table and blocks update/delete; corrections require a new snapshot key. `backend/scripts/seed-ky11-bulk-snapshot.mjs` validates the reviewed SHA-256 `6a59c4d353e7e50ea3c2e9115ca7684763ce55f19ec58598743c4c70a3d5f366` and exact row/provenance counts. It accepts an explicit source path and `RX1011_DATABASE_URL` env file, and requires the expected DB hostname for a write. The `--rehearse` mode applies the migration and insert in a rolled-back transaction; `--apply` commits. A repeated application with identical bytes is a no-op, and a different file at the same key fails.

The table is independent of inventory, stock movements, dispense history, and patient records. The CSV does not include patient names or IDs. The report builder continues to allocate purchases and patient names using its existing algorithm at generation time.
